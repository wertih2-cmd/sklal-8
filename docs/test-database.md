# Тестовая база и e2e

Сейчас вся работа идёт в одной рабочей базе (Supabase `lbbmiwqodiqmkjqhtdmd`). Тестовая база нужна, чтобы миграции, SQL-тесты и e2e сначала прогонялись на копии. Ниже порядок действий. Он НЕ проверен целиком: я не могла создать проект Supabase и накатить на него миграции, поэтому шаг 3 может потребовать правок.

## 1. Создать второй проект
1. В Supabase создайте новый проект (любое имя, например `sklad-test`). Запишите его ref (часть адреса до `.supabase.co`).
2. В Authentication отключите подтверждение почты (Confirm email), иначе e2e-проверка самостоятельной регистрации будет пропущена.
3. Ключ `service_role` и пароль базы храните только у себя, в оболочке. В репозиторий их не кладите.

## 2. Накатить схему
Вариант через Supabase CLI (если он у вас установлен):

    supabase link --project-ref <test-ref>
    supabase db push

Файлы берутся из `supabase/migrations` по порядку имён. Если какая-то миграция упадёт на пустой базе (например, она ждёт данных, которые есть только в рабочей), пришлите мне текст ошибки: это покажет, где миграции нельзя применять с нуля.

## 3. SQL-тесты
В SQL-редакторе тестового проекта по одному выполняйте файлы из `supabase/tests`. Каждый откатывает данные сам и заканчивается ошибкой `ОТЧЁТ`. Ожидаемые числа проверок: payroll 67, manager_rights 37 (проверьте по меткам в файле), tasks 34.

## 4. Данные для e2e
Скрипт `scripts/seed-test-db.mjs` создаёт пользователей (админ, супервайзер, менеджер, отключённый), здание, три квартиры и двух хаускиперов. Он отказывается работать, если адрес совпадает с рабочим проектом.

    E2E_ALLOW_SEED=1 E2E_SUPABASE_URL=https://<test-ref>.supabase.co E2E_SERVICE_ROLE_KEY=... \
    E2E_ADMIN_PASSWORD=... E2E_SV_PASSWORD=... E2E_MANAGER_PASSWORD=... E2E_DISABLED_PASSWORD=... \
    npm run seed:test

В конце он печатает значения для e2e.

## 5. Запуск e2e
Один раз установите браузер: `npx playwright install chromium`. Затем:

    E2E_ALLOW=1 E2E_SUPABASE_URL=https://<test-ref>.supabase.co E2E_SUPABASE_ANON_KEY=<anon key> \
    E2E_ADMIN_LOGIN=e2e_admin E2E_ADMIN_PASSWORD=... E2E_SV_LOGIN=e2e_sv E2E_SV_PASSWORD=... \
    E2E_DISABLED_LOGIN=e2e_disabled E2E_DISABLED_PASSWORD=... E2E_QR_APARTMENT_ID=<id из скрипта> \
    npm run e2e

Приложение для e2e собирается с переменными тестового проекта: в `.env.local` (он не коммитится) укажите адрес и anon-ключ ТЕСТОВОГО проекта на время прогона. Не запускайте e2e со ссылкой на рабочую базу.
